# 元数据嵌入与内嵌字幕 / 歌词

写进媒体文件内部的内容分两类，入口不同、开关互不影响：

| 类别 | 内容 | 由谁决定 | 入口 |
| --- | --- | --- | --- |
| 元数据 | 标题、艺术家、专辑、备注、封面等标签，播放器用来显示和整理媒体 | 全局设置，对此后所有下载生效 | **设置 → 下载 → 为下载文件添加元数据 / 元数据选项** |
| 内嵌字幕与歌词 | 视频文件里的软字幕轨、音频文件里的歌词字段 | 每次下载在解析页单独勾选 | **解析页 → 下载与导出 → 内嵌字幕 / 内嵌歌词** |

产品将作品标签与字幕、歌词分开选择。技术上歌词通常保存在标签字段中，但是否写入歌词由解析页决定，与「添加元数据」开关无关。选项只影响此后完成的下载，不修改已经保存的文件。

## 元数据：信息来源与含义

| 内容 | 标题 / 艺术家 | 专辑 / 编号 |
| --- | --- | --- |
| 单 P 视频 | 稿件标题；可用 UP 主补充艺术家 | 只有真实的 UP 主合集才填专辑；不凭列表位置编造曲序 |
| 多 P 视频 | 当前分 P 标题；可用 UP 主补充艺术家 | 稿件标题作为所属作品；使用官方 page / pageCount |
| 番剧、影视 | 单集标题及 long_title；不将上传账号或演员名单当歌手 | 季/作品名；只有明确数字集号才填曲序，SP、PV 不猜编号 |
| 课程 | 课时标题；可用课程 UP 主补充艺术家 | 课程名；官方课时编号 |
| 音频区 au | 歌曲标题；优先使用 author，缺失时才考虑 UP 主 | 接口未提供真实专辑，不拿歌名或歌单名填充 |
| 收藏夹、稍后再看、空间、歌单中的条目 | 补取条目本身的信息 | 这些列表本身不充当专辑或作品，也不提供曲序、作者、发布时间 |
| 图文、封面图片、弹幕等附加文件 | 不应用音视频标签 | — |

- 视频封面取该稿件的封面，音频区取该歌曲的封面，不拿列表封面或分 P 首帧代替。
- UP 主、简介、普通 TAG、B 站发布时间和原始内容链接在备注中保留原义。普通 TAG 不是音乐流派，上传时间不是唱片发行或录制时间。
- 已标记为转载的视频不将 UP 主填入艺术家。音频区的 author 与 uname 分开处理，不从标题、简介、LRC 的署名猜测作词、作曲、流派或专辑艺术家。
- 多 P 作品优先按稿件归组，避免将每个稿件内部的 P1/P2 错当整个合集的轨道序号。合集没有可靠的全局音轨编号时留空。
- 番剧、课程只有当前完整列表的数字编号连续且从 1 开始时才填写总轨数；不拿已加载一页的长度当总数。
- 原始链接指向当前内容；视频分 P 带 `?p=`，课程和番剧定位到具体 ep。重试优先按 cid 找回原下载单元，曲序不再承担资源身份。

### 元数据选项与默认值

| 选项 | 默认 | 行为 |
| --- | --- | --- |
| 嵌入封面 | 开 | 下载并校验图片，保持比例，限制解码尺寸后嵌入兼容的 JPEG |
| 用 UP 主补充艺术家 | 开 | 优先使用音频区歌曲作者；视频音轨等未提供作者的内容，用 UP 主填入艺术家供播放器显示。已标记的转载视频和番剧只在备注保留 UP 主；关闭此项也不影响已知的歌曲作者 |
| 将合集作为专辑 | 开 | 使用真实 UGC 合集；不改变多 P 作品、课程、剧集自身的归组 |

## 内嵌字幕（视频）

解析页输出类型为「音视频」或「仅视频」时显示「内嵌字幕」分组。字幕以**软字幕轨**写入容器，供播放器切换或关闭，不渲染到画面里。

保存字幕文件、嵌入视频字幕、嵌入音频歌词使用同一份可用语言目录：前两者多选，歌词单选。选择面板在语言名称后显示小型圆角 `AI` 标签；摘要、下载详情、字幕任务名称和视频轨道标题保留「英语 · AI 字幕」这样的完整名称。来源来自 B 站的 AI 标记或 `ai-` 语言代码，不依赖上游名称是否带「自动生成」。没有 AI 标记的字幕也不擅自宣称为人工制作。

解析页显示紧凑的语言摘要，点击打开 Material 3 底部面板。面板使用无边框列表，视频字幕为复选框、歌词为单选按钮；选择先作为草稿，点击「完成」后应用，取消、返回或向下关闭均不改变原选择。每行至少 48 dp 可点击区域，先裁剪圆角再绘制按压涟漪；长列表独立滚动，底部操作按钮保持可见。

AI 标签仅说明来源，点击仍选择整行；大字体时自然换行，读屏保留完整的「AI 字幕」含义。

界面统一使用「嵌入到视频文件」「嵌入到音频文件」。字幕与歌词选项不常驻解释轨道、标签的实现方式；只有输出将改为 MP4、转换 MP3 将丢失 Atmos，或选择不完整、加载失败等需要处理的情况才显示提示。批量语言面板通过各行覆盖数量说明可用范围，不再附加重复的“未完成项”说明；选择全部字幕时按各条目自身可用字幕处理，不把语言目录不同误报为选择缺失。本次文案整理限定于修改涉及的字幕、歌词与相关偏好，流媒体格式的阅读提醒、DASH 自动合并提示和其他既有说明保持原样。

| 情形 | 行为 |
| --- | --- |
| 单个条目 | 可选择全部字幕，或明确选择若干语言；指定集合为空时要求补选，不自动退回全部 |
| 批量下载 | 汇总所选条目的语言目录，展示每种语言的可用条目数；明确选定的语言集合逐条应用，不换成其他语言 |
| 全选 | 与列表的真实勾选状态一致；部分选择显示半选，空选择显示未选。全选包含所有 AI 来源，不再叠加独立的 AI 筛选开关 |
| 字幕目录加载 | 有限并发查询；成功结果在本轮解析中缓存，切换批量选择后重新汇总，失败项支持重试 |
| 字幕查询失败 | 保留用户已做的选择并显示失败状态，不能将网络错误当成「没有字幕」而关闭功能 |
| 未登录时目录为空 | 提示登录后获取字幕，不断言视频本身没有字幕；登录状态变化后重新查询 |
| 当前条目没有匹配语言 | 不擅自改选别的语言；下载阶段报告具体未完成的语言 |
| FLV 且选中内嵌字幕 | 本次任务改为 MP4 输出，并在解析页提示；不改全局转码开关，兼容音视频轨直接复制 |

FLV 的 `onTextData` 数据标签不等于通用播放器可切换的多语言字幕轨，因此该功能只使用 MP4 或 MKV。这里是播放器互操作性取舍，不是宣称 FLV 完全不能存放文本。

流媒体格式的可用性与字幕封装是两个问题。本地接口文档明确普通视频 web playurl 已下线 FLV，因此普通视频直接将 FLV 置灰；番剧、课程不套用这一结论。成功取流实际返回其他格式时，按当前资源记录不可用格式并选中实际返回格式；网络失败不作为能力证据。批量选择汇总当前条目的已知限制，重新解析或登录状态变化后清除探测记录，不为探测容器额外请求接口。

不可用格式只显示禁用状态，长按或悬停可查看原因；没有任何共同格式、必须调整选择时才常驻提示。格式帮助保留原有入口及说明。

轨道写法：

- MP4 使用 `mov_text`（tx3g）编码；MKV 直接保存 SubRip 文本。两者都通过 FFmpeg 以流复制完成，原音视频不重编码。
- 每条轨道写入 ISO 639-2 语言码：MP4 用 T 码（`zho`、`eng`），Matroska 用 B 码（`chi`、`eng`）。B 站的 `zh-Hans`、`ai-en` 等标签先去掉 `ai-` 前缀与地区 / 脚本子标签，再由 `Locale` 换成三字母码，见 `SubtitleLanguageCodes`；简繁差异三字母码表达不了，交给轨道标题保留。未知语言写 `und`。
- 轨道标题保留语言区别并明确标注 AI 来源（如「中文（简体）」「英语 · AI 字幕」）。MP4 同时写入 `handler_name`，供使用 `hdlr` 名称的播放器显示。
- 只有第一条轨道标为默认轨，其余显式清零。具体播放器仍可按其自身语言或字幕偏好决定初始状态。
- 重试或再次保存时，输出里的字幕轨只来自本次选择，原有字幕轨不再映射，轨道不会翻倍；不嵌入字幕的普通元数据改写则保留文件里已有的字幕轨。
- 每种语言单独获取：个别语言失败只影响那一条，其余照常嵌入。下载时再次查询发现已选语言消失，也列入未完成项；不能因其余语言成功就遗漏提示。没有有效字幕行的空文件按不可用处理。

## 内嵌歌词（音频）

输出类型为「仅音频」时显示「内嵌歌词」分组。为保持播放器兼容性与选择方式清楚，产品规定**每个文件选一种歌词语言**。这不是 FLAC 的硬性限制：Vorbis Comment 可以包含重复字段，但多语言歌词并没有统一的播放器切换约定。

| 来源 | 行为 |
| --- | --- |
| 音频区歌曲 | 写入歌曲自带的原始 LRC（song/info 的 lyric，缺失时查询 song/lyric）；与关联视频的字幕无关。原始 LRC 保留时间戳、多时间戳及 offset，不拆分其中可能已有的双语文本 |
| 视频 / 番剧 / 课程转出的音频 | 由用户明确选择一种字幕转成 LRC；未选择时要求补选，不再使用人工、简体、繁体等隐式优先级 |
| 批量下载 | 对所选条目应用同一种明确语言；缺失时报告，不逐条自动换语言 |
| 杜比全景声 | 保留 E-AC-3 音轨，输出音频 MP4（`.m4a`），可写歌词；无需转换为 MP3 |

E-AC-3 是编码；MP4 是容器；`.m4a` 是音频 MP4 的常见命名约定，不是 Dolby 指定的唯一标准后缀，也不意味着音频转成了 AAC。`.ec3` 与 `.eac3` 通常用于裸 E-AC-3 码流。当前输出以标准 MP4 容器保存原音频，使用 `.m4a` 与 `audio/mp4`，同时承载封面和歌词。

字幕按开始时间转换为 LRC，保留停顿的清屏时间，过滤外部响应中的无效时间。AI 字幕指 B 站已有的 AI 字幕，本功能不生成或翻译歌词；来源语言及 AI 标识记录在下载详情的「内嵌歌词」一栏。不同播放器对内嵌 LRC 的滚动显示支持不同，仍可读取歌词文本。

## 记忆下载偏好

**设置 → 下载 → 记忆下载偏好** 决定解析页「下载与导出」卡片里的哪些选项跨次解析保留。总开关之下按卡片分区逐组选择：输出类型、流媒体格式、分辨率与视频编码、音频比特率、内嵌字幕与歌词、字幕文件与 AI 总结、NFO 元数据、弹幕、图像、图文。

- 默认保留内嵌与各类附加导出项（它们没有别的默认来源），不保留输出类型、流格式与画质音质（各有自己的默认设置，每次解析回到默认值）。
- 只记住用户实际操作的字段。只改视频编码时不覆盖分辨率；只取消封面时不清掉当前资源没有提供的首帧偏好；资源不可用导致的临时调整不写回。
- 「默认下载质量」与记住的上次选择分别保存。启用画质或音质记忆时优先使用已记住的字段，未记住的字段继续使用默认值；关闭记忆后恢复默认质量，不会发现默认值被解析页改低。
- 指定的字幕语言只在当前解析过程中使用；新一次解析重新选择。历史弹幕的日期与小时每次解析重置，避免对新资源沿用旧日期。
- 入口行以一句话汇总当前保留的分组；总开关关闭时，页面说明所有选项每次都回到默认值，分组开关变灰但保留原值。

## 容器与写入安全

| 输出 | 写入方式 | 封面 | 字幕轨 | 歌词 |
| --- | --- | --- | --- | --- |
| MP3 | jaudiotagger 标准 ID3 | APIC，正面封面类型 3 | — | USLT |
| FLAC | jaudiotagger Vorbis Comment / PICTURE | PICTURE，记录真实尺寸 | — | LYRICS |
| M4A / MP4 | 标准 MP4 标签 | covr / attached_pic，不增加普通视频轨 | 视频输出使用 mov_text 轨，T 码语言 | 音频输出使用 ©lyr |
| MKV | FFmpeg 流复制 | JPEG 附件，按方向命名 cover.jpg / cover_land.jpg | SubRip 轨，B 码语言 | 视频混流输出，不写歌词 |
| FLV | FFmpeg 流复制，只加文字标签 | 不强塞不受支持的封面轨 | 选中内嵌时，本次输出 MP4 | 视频输出，不写歌词 |
| 杜比 E-AC-3 | 音频 MP4（`.m4a`） | 与 M4A 相同 | — | 与 M4A 相同 |

仅音频、仅视频下载在写标签前完成封装处理，关闭元数据、歌词或字幕也不跳过。DASH FLAC 输出原生 FLAC；杜比音轨使用 `.m4a` 与 `audio/mp4`，不把 MP4 内容改名成原始 `.ec3`，也不使用 `.eac3.ec3`。仅视频的 DASH 下载整理为常规 `.mp4` 与 `video/mp4`；`.m4s` 只用于描述上游分片或内部临时输入，不作为最终下载文件的扩展名。

MP4 转换与音视频合并在系统边界通过 FFprobe 读取实际音频编码。AAC、AC-3、E-AC-3、MP3、ALAC 直接复制；FLAC 等采用明确的 AAC 192 kbps 兼容输出策略。视频始终直接复制，不能装入 MP4 的视频编码会报告转换失败，不偷偷进行视频有损转码。未选择转 MP4 的无损音视频仍使用 MKV 保留 FLAC。MP4 保留处理 Dolby Vision 所需的 `-strict unofficial`。

### 杜比 Atmos 配置保留

E-AC-3 数据包中含有 JOC 信息，并不意味着 MP4 的 Atmos 标记一定正确。当前 Android FFmpeg 库基于 FFmpeg 6；该版本重建 MP4 时会丢失 `dec3` 的可选 JOC 扩展。主机 FFmpeg 7.1.1 同样可复现：官方样本原始 `dec3` 载荷是 `1400200f000110`，流复制后变为 `1400200f0000`；即使全部音频包哈希一致、ffprobe 仍显示 Atmos，也不能据此断言容器标记被保留。

`Mp4DolbyConfiguration` 是针对这个已验证上游缺陷的集中修复。它沿 ISO-BMFF 标准 box 路径读取源 `dec3`，支持 DASH 初始化 `moov`，将源 Atmos 配置补回 FFmpeg 的常规 MP4 临时产物。必要时将新 `moov` 写到文件末尾，旧 `moov` 原位改为 `free`，不移动媒体数据，也不重写 `stco` / `co64`。因此发生修复的文件使用标准的末尾索引布局，不再保留 faststart 的前置索引；本地播放不需要重新编码。普通 E-AC-3、已经保留配置的输出，以及显式转成 AAC 的输出不作此修改。

修复统一用于音频整理、音视频合并、MP4 转换及标签/字幕写入；只有全部处理成功后才保存临时产物。将来升级到包含 [FFmpeg 上游 Atmos muxer 修复](https://ffmpeg.org/pipermail/ffmpeg-devel/2025-June/344716.html)的版本时，应以真实样本回归为依据移除这一辅助层。

MP3 使用标准 USLT 而不是 FFmpeg 6 将未知 `lyrics` 字段写出的 TXXX；歌词和备注帧使用 `und` 表示未声明语言，不猜英文或中文。FLAC 图片直接写 PICTURE 字段，绕开 jaudiotagger 对 AWT / ImageIO 的依赖。

所有标签修改先在同目录临时副本完成，完成后再替换。封面、字幕或歌词请求失败不会阻止其余内容；写入失败保留原文件，在下载完成信息中逐项提示缺失（`EmbeddedContentIssue`），并记录诊断日志。字幕临时文件创建后立即登记到清理范围，暂停或取消第二条字幕时也会清理已创建的第一条。图片和原始 LRC 下载设有大小上限，编码错误及 HTML/JSON 错误响应不作为歌词保存。下载详情区分请求内容、实际写入内容和未完成项。

本功能尚未公开发布，不保留旧歌词开关的迁移、旧设置键或 `metadataWarning` 的 JSON 字段别名。其他功能已有的迁移不因本次调整而删除。

保存到系统下载目录时，只认可本次新建、已发布且实际可读的 URI，不能把同名旧文件当作本次成功结果。覆盖模式先完成新文件，再删除同目录的旧文件并恢复请求名称；创建、写入或发布失败时保留旧文件与已下载的源数据。`DownloadOutputSaveTest` 使用真实文件描述符及模拟 ContentProvider 验证失败和覆盖顺序。

## 验证

验证分为可复现单元测试、主机 FFmpeg 容器往返与 UI 检查：

- 元数据映射、字幕时间轴、显式语言匹配、AI 来源名称、丢失语言提示与写入失败隔离。
- 批量目录缓存、有限并发、失败重试，以及没有字幕和请求失败的区分。
- 默认质量与记忆分离、编码单字段修改、图片偏好增删及历史弹幕日期重置。
- 真实 MP3 / FLAC 标签回读，MP4 / MKV 字幕轨的语言、标题、默认轨和字幕内容回读。
- 浅色与深色的内嵌选项、批量选择、AI 标识、设置页和窄屏大字体。

可选的主机容器集成测试需要 FFmpeg / FFprobe。Windows 示例：

```powershell
$env:BILITOOLS_TEST_FFMPEG = 'C:/path/to/ffmpeg/bin'
./gradlew.bat :app:testDebugUnitTest
```

`EmbeddedContainerRoundTripTest` 生成 MP4、分段 MP4、M4A、MKV、FLV，回读标签、封面和字幕，并比较原音视频包的 SHA-256。`MediaOutputRoundTripTest` 另验证 E-AC-3 的 M4A 歌词写入、无标签时的 FLAC 解封装、FLV 中 AAC 无损换容器、FLAC 转 MP4 的兼容策略。未设置该环境变量时跳过依赖主机工具的测试。临时产物在 `.tmp/metadata/` 与 `.tmp/media-output-tests/`，不连接设备。

`Mp4DolbyConfigurationTest` 使用合成 box 验证父级大小、多个音轨、64 位 box 头、分片源的初始化配置、媒体数据位置不变、无需修复时不改文件，以及非法边界在写入前失败。

官方 Atmos 样本另通过环境变量启用，不下载或分发测试媒体到版本库：

```powershell
$env:BILITOOLS_TEST_ATMOS_SAMPLE = 'C:/path/to/.tmp/dolby-atmos-avsync.mp4'
./gradlew.bat :app:testDebugUnitTest --tests '*MediaOutputRoundTripTest'
```

样本来自 [Dolby Digital Plus Online Delivery Kit v1.4.1 的 MP4 测试页](https://ott.dolby.com/OnDelKits/DDP/Dolby_Digital_Plus_Online_Delivery_Kit_v1.4.1/Test_Signals/muxed_streams/MP4/MP4_Muxed_Streams.html)，文件为 [AVSync H.264 / 25 fps / 640 kbps DDP JOC](https://ott.dolby.com/OnDelKits/DDP/Dolby_Digital_Plus_Online_Delivery_Kit_v1.4.1/Test_Signals/muxed_streams/MP4/Example/AVSync_1280x720p_25fps_h264_6ch_640kbps_ddp_joc.mp4)。2026-09-17 下载的文件大小为 15,123,330 字节，SHA-256 为 `872267d4d3b9ba623420464ae9759567b2530c936879a4dfb86e1ccc64e607e8`。该样本仅用于测试，保存在 `.tmp/`。回归覆盖原始 `dec3` 扩展、音频包哈希、M4A 歌词与封面、视频合并及软字幕/封面写入后的配置和媒体保留。

这些测试验证文件结构与数据保留，不等于真机播放器兼容性认证。系统播放器、MX Player、Kodi 等的字幕切换、歌词滚动显示，以及实际 Atmos 解码与声音路由，仍取决于播放器与设备，未使用 adb 声称完成验证。

测试资源 `app/src/test/resources/metadata/` 为 FFmpeg 生成的 0.25 秒 440 Hz 正弦波和 64×48 纯蓝图片，不包含真实用户音频。生成参数见集成测试中的 lavfi 用法。
